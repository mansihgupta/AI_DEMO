AWS Bedrock Agent Security POC

Objective

Build a low-cost Proof of Concept (POC) to validate:

  • PingFederate authentication (First Mile)
  • Temporal session controls
  • Cedar fine-grained authorization
  • Bedrock Agent orchestration
  • Least-privilege outbound access (Last Mile)

The architecture is intentionally incremental so each capability can be validated independently while keeping AWS costs near zero when idle.

Design Principle: Authentication, authorization, and temporal validation should occur before any LLM invocation to reduce costs and improve security.

Phase 1: Foundation and First Mile Security

Goal

Deploy the minimum infrastructure required to validate identity and inbound access.

Components

  • Amazon Bedrock Agent
  • IAM Execution Role
  • API Gateway
  • PingFederate OIDC Provider
  • Mock Lambda Endpoint

Implementation Steps

  1. Create Bedrock Agent execution role.
  2. Attach minimum required Bedrock permissions.
  3. Configure API Gateway.
  4. Integrate PingFederate using OIDC.
  5. Implement token introspection endpoint validation.
  6. Forward validated claims downstream.

Recommended Flow

     |

     |
     v

     |
     +--> Token Introspection
     |
     v
Validated Claims

Validation Test

  • Generate valid JWT from PingFederate.
  • Call API Gateway.
  • Verify claims reach backend.
  • Verify unauthorized tokens are rejected.

Phase 2: Session Lifecycle and Temporal Controls

Goal

Ensure sessions automatically expire and access is denied after approved windows.

Claims to Capture

  • sub
  • auth_time
  • exp
  • department
  • session_clearance

Implementation Flow

PingFederate Token
       |
       v
Authorizer
       |
       +--> Verify exp claim
       +--> Verify auth_time
       |
       v
Session Attributes

Session Attributes Example

{
  "sessionAttributes": {
      "userEmail": "john.doe@company.com",
      "department": "Finance",
      "sessionClearance": "Standard",
      "tokenExpiry": "1791244800"
  }
}

Security Controls

  • Reject expired sessions.
  • Reject sessions exceeding maximum lifetime.
  • Terminate agent execution before model invocation.

Validation Test

  1. Invoke agent with valid session.
  2. Verify response succeeds.
  3. Allow token to expire.
  4. Repeat request.
  5. Verify rejection before LLM invocation.

Phase 3: Cedar Fine-Grained Authorization

Goal

Authorize actions using Cedar before retrieval, prompting, or tool execution.

Authorization Pattern

Request
   |
   v

   |
   v

   |
   +--> Deny
   |
   +--> Allow
           |
           v
       Bedrock Agent

Example Cedar Policy

permit(
    principal,
    action == Action::"ExecuteTool",
    resource == Resource::"InternalFinanceData"
)
when {
    principal.department == "Finance"
};

Recommended Protected Resources

  • HR Systems
  • Finance Databases
  • Payroll Information
  • Corporate Knowledge Bases
  • Sensitive APIs

Validation Test

Finance User

department = Finance
resource = InternalFinanceData
Expected Result = ALLOW

Engineering User

department = Engineering
resource = InternalFinanceData
Expected Result = DENY
Successful authorization should occur before any LLM token consumption.

Phase 4: Bedrock Agent Integration

Goal

Connect identity-aware authorization with Amazon Bedrock Agent execution.

Agent Responsibilities

  • Process user requests.
  • Invoke approved tools.
  • Respect Cedar decisions.
  • Use validated user context.

Suggested Foundation Model

  • Claude 3.5 Haiku

This model offers low latency and minimal cost while testing orchestration logic.

Goal

Example Runtime Session Policy

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "lambda:InvokeFunction",
      "Resource":
      "arn:aws:lambda:us-east-1:123456789012:function:MockEchoAPI"
    }
  ]
}

Security Objectives

  • Prevent lateral movement.
  • Limit downstream privileges.
  • Constrain resources to current request context.
  • Create an auditable identity chain.

Validation Test

  1. Invoke Lambda tool.
  2. Capture identity headers.
  3. Verify department attribute.
  4. Verify user ID.
  5. Verify session constraints.

Recommended AWS CLI Workflow

Create Execution Role

aws iam create-role \
  --role-name AgentCore-POC-ExecutionRole \
  --assume-role-policy-document file://trust-policy.json

Attach Bedrock Permissions

aws iam attach-role-policy \
  --role-name AgentCore-POC-ExecutionRole \
  --policy-arn arn:aws:iam::aws:policy/AmazonBedrockFullAccess

Create Agent

aws bedrock-agent create-agent \
  --agent-name "secure-poc-agent" \
  --agent-resource-role-arn "ROLE_ARN" \
  --foundation-model "anthropic.claude-3-5-haiku-20241022-v1:0"

Invoke Agent

aws bedrock-agent-runtime invoke-agent \
  --agent-id "AGENT_ID" \
  --agent-alias-id "ALIAS_ID" \
  --session-id "session-001" \
  --input-text "Retrieve travel updates"
